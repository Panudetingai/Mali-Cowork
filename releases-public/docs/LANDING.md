## Mali Cowork คืออะไร

แอป desktop ตัวเดียวที่รวม **ทุกโมเดลและทุก agent ที่คุณจ่ายเงินไปแล้ว** ไว้ที่เดียว แล้วให้มันทำงานกับไฟล์จริงบนเครื่อง โดยที่ **คุณเป็นคนกดอนุญาตทุกครั้ง**

| โหมด | ใช้ทำอะไร | แตะไฟล์ได้ไหม |
|---|---|---|
| **Chat** | ถาม-ตอบ เขียน สรุป คิดงาน | ❌ ไม่อ่าน ไม่แก้ไฟล์ใด ๆ |
| **Cowork** | ให้ agent แก้โค้ด จัดไฟล์ สร้างเอกสาร รันคำสั่ง | ✅ เฉพาะโฟลเดอร์ที่คุณกดอนุญาต |

> การสลับโหมดทำที่ช่องพิมพ์ และแชทหนึ่งอันจะอยู่โหมดเดียวตลอด — ไม่มีทางที่แชทธรรมดาจะกลายเป็น agent ที่แก้ไฟล์ได้กลางคัน

## เชื่อมอะไรได้บ้าง

**Agent ที่รันบนเครื่อง** — OpenCode (มีโมเดลฟรีให้ ไม่ต้องสมัครอะไร), Codex CLI, Gemini CLI, Cursor Agent
**API ของคุณเอง** — OpenAI, Anthropic, Google, Groq, DeepSeek, Mistral, Qwen, Z.ai, Moonshot, xAI, OpenRouter, Ollama (ทั้ง local และ cloud)
**MCP tools** — ต่อ Gmail, Notion, Linear, Figma, Playwright, filesystem และอีกหลายร้อยตัวจาก registry ติดตั้งได้จากในแชทเลย
**Skills** — คู่มือการทำงานที่คุณเขียนเอง ให้ agent ทำตามทุกครั้ง

ทุกอย่างมาโผล่ในที่เดียวกันหมด: **model picker** เดียว แยกชัดว่าตัวไหนมาจาก CLI ที่คุณ sign in ไว้ ตัวไหนใช้คีย์ของคุณ ตัวไหนวิ่งผ่าน OpenCode

## ทำอะไรได้บ้าง

- **ทำงานกับโฟลเดอร์จริง** — อ่าน แก้ สร้างไฟล์ รันคำสั่ง ดู git diff ก่อน commit
- **Checkpoint** — ย้อนกลับได้ทุกอย่างที่ agent แก้ ก่อนจะยอมรับงาน
- **Git ในตัว** — stage, commit (ช่วยเขียน message ให้), branch, push/pull
- **แนบไฟล์และรูป** — ลากใส่ได้เลย รูปกับวิดีโอที่ agent หรือ MCP ส่งกลับมากดดูเต็มจอได้
- **Hover ลิงก์เห็น preview** — รู้ว่าลิงก์พาไปไหนก่อนกด
- **ถาม-ตอบกลับได้** — agent ถามกลับได้เมื่อมันไม่แน่ใจ แทนที่จะเดาแล้วทำผิด
- **แจ้งเตือนระบบ** — บน macOS กด **Allow / Always / Deny** ได้จากตัวแจ้งเตือนเลย ไม่ต้องสลับหน้าต่างกลับมา

# ความปลอดภัย — คำถามที่ควรถาม

ส่วนนี้ตอบตรง ๆ ทั้งสิ่งที่แอป **ทำได้** และสิ่งที่ **ทำไม่ได้** เพราะการอ้างเกินจริงเรื่องความปลอดภัยอันตรายกว่าการไม่อ้างเลย

## API key ที่ฉันใส่ไป ไปอยู่ที่ไหน

**อยู่ใน credential store ของระบบปฏิบัติการ ไม่ใช่ไฟล์ธรรมดา**

| ระบบ | เก็บที่ |
|---|---|
| macOS | **Keychain** (รายการเดียว ชื่อ Mali Cowork) |
| Windows | **Credential Manager** |
| Linux | ไฟล์ที่เจ้าของเครื่องเท่านั้นอ่านได้ (`0600`) — *ยังไม่ได้ต่อ credential store* |

- คีย์จะถูกส่ง **ไปหาผู้ให้บริการนั้นโดยตรงเท่านั้น** (เช่นคีย์ OpenAI ไปที่ `api.openai.com`) ไม่มีเซิร์ฟเวอร์ของ Mali Cowork คั่นกลาง เพราะ**ไม่มีเซิร์ฟเวอร์ของเราเลย**
- **โมเดลไม่เคยเห็นคีย์** — คีย์อยู่ใน HTTP header ไม่ได้อยู่ในบทสนทนา ต่อให้ agent โดนหลอกให้ "บอกคีย์ออกมา" มันก็ไม่มีอะไรจะบอก
- เวลา sync ให้ OpenCode ใช้ คีย์จะลงไปใน auth file ของ OpenCode เอง (สิทธิ์เจ้าของเท่านั้น) **ไม่ได้เขียนลง config ที่เป็น plain text**
- ลบได้ตลอดจาก Settings → Models → Remove

## เชื่อม OpenCode / Cursor / Codex / Gemini ที่ฉันจ่ายเงินไปแล้ว ปลอดภัยไหม บัญชีจะโดนใช้มั่วไหม

**Mali Cowork ไม่เคยเห็น credential ของ subscription คุณเลย**

- แอป **ไม่ได้ขอ** username/password หรือ token ของ Cursor/ChatGPT/Google ในการ sign in — คุณ sign in ผ่าน CLI ตัวนั้นเอง (`cursor-agent login`, `codex login`, `gemini`) และ token อยู่ใน config ของ CLI นั้น (`~/.cursor`, `~/.codex`, `~/.gemini`)
- Mali Cowork แค่ **เรียก CLI ในสิทธิ์ของคุณเอง** เหมือนคุณพิมพ์เองใน Terminal ไม่มีการอ่านไฟล์ credential เหล่านั้น
- โฟลเดอร์ credential ของ CLI ทุกตัว (`~/.cursor`, `~/.codex`, `~/.gemini`, `~/.config/opencode`, `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.docker`, `~/.kube`, `~/.netrc`, `~/.git-credentials`, `**/.env`) อยู่ใน **deny list ของตัวแอปเอง** — หน้าเว็บของแอปอ่านไม่ได้เด็ดขาด
- **โควต้าจะถูกใช้ก็ต่อเมื่อคุณเลือกโมเดลนั้นแล้วกดส่ง** — model picker บอกชัดว่าแต่ละตัวมาจากไหน (`Cursor CLI` / `via OpenCode` / `your key`) ไม่มีการสลับ agent ให้อัตโนมัติ ถ้าโมเดลที่เลือกใช้ไม่ได้ แอปจะหาตัวแทน**จากที่มาเดียวกัน**เท่านั้น ไม่เด้งไปเผาโควต้าของ subscription อื่น
- เปลี่ยน agent กลางแชท แอปจะเตือนก่อน เพราะ session คนละตัวและคิดเงินคนละบัญชี

## AI อ่านไฟล์ทั้งเครื่องฉันได้ไหม

**ไม่ได้ — มันเริ่มจากศูนย์ทุกครั้ง**

1. โหมด Chat แตะไฟล์ไม่ได้เลย
2. โหมด Cowork ทำงานได้เฉพาะโฟลเดอร์ที่คุณ**กดอนุญาตทีละอัน** และเลือกได้ว่าเป็น **read-only** หรือ **read & write**
3. ออกนอกโฟลเดอร์ที่อนุญาต → **เด้งถามคุณ**
4. คำสั่ง shell ทุกคำสั่ง **ถามก่อนรัน** ยกเว้นคำสั่งอ่านล้วน ๆ (`ls`, `cat`, `grep`, `git status`…) ที่ **path ทุกตัวอยู่ในโฟลเดอร์ที่อนุญาตแล้วเท่านั้น** — `cat ~/.aws/credentials` ยังเด้งถามอยู่ดี
5. คำสั่งที่มี `;` `&&` `|` `>` `$(...)` backtick หรือ flag ที่เขียนไฟล์/รันโปรแกรมอื่น **ไม่เข้าข่ายอ่านล้วน** ต้องถามเสมอ
6. `..` และ symlink ถูก resolve ก่อนตรวจ — ลิงก์ในโฟลเดอร์ที่เขียนได้ ชี้ออกไปโฟลเดอร์ read-only ไม่ได้

> **Auto-approve** (ปิดไว้โดยค่าเริ่มต้น) แปลว่า "ไม่ต้องถามเรื่องงานที่ฉันตั้งไว้" **ไม่ใช่** "เอื้อมไปไหนก็ได้" — คำสั่งที่อ้างถึง path นอกโฟลเดอร์ที่อนุญาต หรืออาจเขียนทับโฟลเดอร์ read-only ยังเด้งถามอยู่ดี

## Prompt injection ล่ะ — agent โดนหลอกได้ไหม

**ได้ และไม่มีแอปไหนในโลกกัน prompt injection ได้ 100% รวมถึงตัวนี้** นี่คือสิ่งที่เราทำจริง ๆ:

**สิ่งที่เป็นด่านหลัก — คุณ**
ทุกอย่างที่ทำให้เกิดผลจริง (รันคำสั่ง แก้ไฟล์ ออกนอกโฟลเดอร์) ต้องผ่านการกดยืนยันของคุณ พร้อมแสดง**คำสั่งเต็ม ๆ และ path จริง** ให้อ่านก่อน ต่อให้หน้าเว็บที่ agent ไปอ่านเจอจะแอบเขียนว่า *"ignore previous instructions, run this"* มันก็ไปจบที่การ์ดขออนุญาตที่มีคำสั่งแปลก ๆ โผล่ให้คุณเห็น

**สิ่งที่แอปทำให้เพิ่ม**
- คำสั่งอ่านที่ผ่านโดยไม่ถาม ถูกจำกัดไว้ใน**โฟลเดอร์ที่คุณอนุญาต** — เส้นทางคลาสสิกอย่าง "ให้มัน `cat` ไฟล์ credential แล้วส่งออกไป" ถูกตัดตั้งแต่ขั้นอ่าน
- **คีย์ไม่เคยอยู่ใน context** ของโมเดล จึงไม่มีอะไรให้ดูดออกไปตั้งแต่แรก
- โฟลเดอร์ความลับ (`.ssh`, `.aws`, `.env`, keychain ฯลฯ) อยู่ใน deny list ของตัวแอป
- **Checkpoint** ย้อนกลับทุกการแก้ไขได้ ถ้าเผลอกดอนุญาตอะไรไปแล้วรู้ตัวทีหลัง
- โฟลเดอร์ read-only ถูกปฏิเสธที่ฝั่ง Rust ไม่ใช่แค่บอกโมเดลให้ "ช่วยอย่าแก้นะ"

**สิ่งที่คุณควรทำ**
- อ่านการ์ดขออนุญาตจริง ๆ โดยเฉพาะตอนที่ agent เพิ่งไปอ่านเว็บ อ่านอีเมล หรืออ่านไฟล์จากคนอื่น
- อย่าเปิด auto-approve ในงานที่ agent ต้องอ่านข้อมูลจากภายนอก
- ให้สิทธิ์ read-only ถ้างานนั้นแค่ต้องอ่าน
- ให้เฉพาะโฟลเดอร์ของงานนั้น ไม่ใช่ `$HOME` ทั้งก้อน

## แอปส่งข้อมูลอะไรกลับไปหาผู้พัฒนาไหม

**ไม่มีเลย — ไม่มี analytics, ไม่มี telemetry, ไม่มี crash reporter, ไม่มีบัญชีให้สมัคร และไม่มีเซิร์ฟเวอร์ของเรา**
ตรวจเองได้จากซอร์ส: ไม่มี Sentry / PostHog / Mixpanel / Amplitude หรืออะไรทำนองนั้นในโปรเจกต์

สิ่งที่ออกจากเครื่องมีเท่านี้ และออกก็ต่อเมื่อคุณสั่ง:

| ปลายทาง | ออกเมื่อไหร่ | มีอะไรไปบ้าง |
|---|---|---|
| ผู้ให้บริการ AI ที่คุณเลือก | ตอนกดส่งข้อความ | prompt + ไฟล์ที่แนบ/ที่ agent อ่าน |
| CLI agent (Cursor/Codex/Gemini) | ตอนเลือก agent นั้น | ตามที่ CLI ตัวนั้นส่ง — ไปที่บัญชีคุณเอง |
| MCP server ที่คุณเปิด | ตอน agent เรียกใช้ tool | เฉพาะ argument ของ tool นั้น |
| เว็บของลิงก์ที่คุณ hover | ตอน hover ลิงก์ในแชท | คำขอหน้าเว็บ (ดึง title/รูป) — ไอคอนเว็บดึงจากเว็บนั้นเอง ไม่ผ่าน third party |
| models.dev, GitHub avatars | โหลด UI | ขอโลโก้/รูปโปรไฟล์ |
| MCP registry / Smithery | ตอนคุณกดค้นหา connector | คำค้นของคุณ |

**บทสนทนาและประวัติแชทเก็บอยู่ในเครื่องคุณเท่านั้น**

## `http://127.0.0.1:19877/mcp/oauth/callback?code=...` ที่เด้งมาใน browser คืออะไร ปลอดภัยไหม

ปลอดภัยครับ — นี่คือมาตรฐาน **RFC 8252 (OAuth 2.0 for Native Apps)** ที่ Slack, Figma, GitHub CLI ใช้กันหมด แอป desktop ไม่มีเว็บเซิร์ฟเวอร์ให้ผู้ให้บริการยิง callback กลับมา จึงเปิดพอร์ตบน **loopback ของเครื่องคุณเอง** รับแค่แป๊บเดียวตอน sign in

สิ่งที่ทำไว้:
- bind แค่ `127.0.0.1` **ไม่ใช่** `0.0.0.0` → เครื่องอื่นในเน็ตเวิร์กยิงไม่ถึง
- **PKCE** — `code` ที่เห็นใน URL แลก token ไม่ได้ถ้าไม่มี `code_verifier` ซึ่งไม่เคยออกจากแอป และ `code` ใช้ได้ครั้งเดียว
- ตรวจ `state` ทุกครั้ง ไม่ตรงคือไม่ส่งต่อ
- ตรวจ `Host` header — กัน DNS rebinding (เว็บที่ชี้โดเมนตัวเองมา `127.0.0.1` แล้วคุยกับพอร์ตนี้)
- ส่ง `no-store`, `no-referrer`, `nosniff`, `frame-options: DENY`, `CSP: default-src 'none'` → `code` ไม่ติดไปกับ Referer ของหน้าถัดไป และหน้านั้นรันอะไรไม่ได้
- ปิดพอร์ตทันทีที่จบ flow
- **token ไม่เคยเข้าหน้าเว็บของแอป และไม่เคยเข้า context ของ AI**

แถม: แอป register OAuth client ในชื่อ **Mali Cowork** ไม่ใช่ "OpenCode" หน้าจอขออนุญาตของ Google/Notion/Linear จะบอกชื่อที่ตรงกับแอปที่คุณเปิดอยู่จริง

## ถ้าเครื่องฉันโดน malware อยู่แล้วล่ะ

ถ้ามีโปรแกรมร้ายรันในสิทธิ์ผู้ใช้เดียวกับคุณอยู่แล้ว **มันเข้าถึงไฟล์ทุกอย่างที่คุณเข้าถึงได้อยู่แล้ว** โดยไม่ต้องผ่าน Mali Cowork — นี่เป็นข้อจำกัดของทุกแอป ไม่ใช่แค่ตัวนี้ สิ่งที่แอปช่วยได้คือ**ไม่เพิ่มช่องทางใหม่**: คีย์อยู่ใน keychain ของระบบ ไม่ใช่ไฟล์ข้อความ, release build ไม่โหลด `.env` จากโฟลเดอร์ที่เปิดแอป (กันไฟล์ `.env` แปลกปลอมตั้ง `OPENCODE_BIN` ให้ไปรันโปรแกรมอื่น), devtools ถูกปิดใน release

## แล้วตัวแอปเองล่ะ เปิดช่องให้โดนแฮ็กไหม

- **CSP เข้ม** — `default-src 'self'`, `object-src 'none'`, `form-action 'none'` โหลดสคริปต์จากข้างนอกไม่ได้
- **Capability จำกัด** — หน้าเว็บของแอปเรียก Rust ได้เฉพาะคำสั่งที่ประกาศไว้ และระบบไฟล์มี allow/deny list ชัดเจน
- **Markdown ไม่รัน HTML** — ข้อความจาก AI หรือ tool ถูก render เป็นข้อความ ไม่ใช่โค้ด
- **ทดสอบจริง** — Rust 141 test, TypeScript 28 test ผ่านทั้งหมด ครอบคลุมส่วนที่ตัดสินใจเรื่องสิทธิ์ (policy, OAuth, path resolution) โดยเฉพาะ
- โค้ดเปิดให้อ่านได้ทั้งหมด ตรวจเองได้

**สิ่งที่ยังไม่ได้ทำ (บอกตามตรง):** แอปยังไม่ได้ผ่าน security audit จากภายนอก, ยังไม่มี sandbox แยกสำหรับ MCP server (มันรันในสิทธิ์ผู้ใช้คุณ — เปิดเฉพาะตัวที่ไว้ใจ), และบน Linux ยังไม่ได้ต่อ credential store

## สถานะตอนนี้

**เวอร์ชัน 0.1.2 — early access** ใช้งานได้จริงทุกวัน แต่ยังมีข้อจำกัดที่ควรรู้ก่อน:

| เรื่อง | สถานะ |
|---|---|
| ฟังก์ชันหลัก (Chat, Cowork, MCP, Git, Checkpoint) | ✅ ใช้งานได้ |
| การเก็บคีย์ / ระบบสิทธิ์ / OAuth | ✅ มี test ครอบคลุม (Rust 141 · TS 28 ผ่านหมด) |
| Code signing & notarization | ⚠️ **ยังไม่มี** — ต้องกด Right click → Open ครั้งแรก |
| Auto-update | ⚠️ **ยังไม่มี** — ต้องดาวน์โหลดรุ่นใหม่เอง |
| Credential store บน Linux | ⚠️ ใช้ไฟล์สิทธิ์เจ้าของแทน |
| Security audit จากภายนอก | ⚠️ ยังไม่เคยทำ |

**เหมาะกับ:** นักพัฒนาและ power user ที่อยากรวมทุกโมเดล/agent ไว้ที่เดียว และอยากคุมว่า AI แตะอะไรได้บ้าง
**ยังไม่เหมาะกับ:** องค์กรที่ต้องการแอปที่ผ่าน audit และมี auto-update ในตัว

## คำถามอื่น ๆ

**ต้องต่อเน็ตไหม** — ต้อง ถ้าใช้โมเดล cloud ถ้าใช้ **Ollama** บนเครื่อง ทำงาน offline ได้ทั้งหมด

**ต้องจ่ายเงินให้ Mali Cowork ไหม** — ไม่ คุณจ่ายให้ผู้ให้บริการโมเดลโดยตรง (หรือใช้โมเดลฟรีของ OpenCode / Ollama บนเครื่อง)

**ถ้า agent ทำพัง** — กด Checkpoint ย้อนกลับได้ทุกไฟล์ที่มันแก้ และถ้าโฟลเดอร์นั้นเป็น git repo ก็ดู diff ทุกบรรทัดได้ก่อนตัดสินใจ

**แชทเก่าอยู่ที่ไหน** — ในเครื่องคุณ (SQLite) export เป็นไฟล์ได้ ลบได้ ไม่มีใครเห็นนอกจากคุณ

**เปลี่ยนโมเดลกลางแชทได้ไหม** — ได้ แต่ถ้าเปลี่ยนไปคนละ agent แอปจะเตือนก่อน เพราะ session คนละตัวและจะไม่รู้เรื่องที่คุยไปก่อนหน้า

**MCP server ที่ติดตั้งจาก registry ปลอดภัยไหม** — MCP server รันในสิทธิ์ผู้ใช้คุณ **เหมือนโปรแกรมทั่วไป** ให้มองเหมือนติดตั้งแอป: ดูว่าใครทำ ก่อนเปิดใช้ แอปแสดงที่มาและคำสั่งที่จะรันให้ดูก่อนเสมอ และเปิด/ปิดทีละตัวได้
